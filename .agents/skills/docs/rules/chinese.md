# 中文写作规范

中文页面应当读起来像以中文为母语的工程师写给同行的技术文档，而不是英文页面的译文。本文件适用于 RPent 的中文文档、PR 描述和中文评审意见。页面类型要求见对应规则文件，术语译法见 [glossary.md](glossary.md)。

## 先理解，再用中文写

中英文页面保持相同的章节结构、命令、参数、数字和链接，但句子不必一一对应。严禁机翻或逐句直译。动笔前先明确本段要交代什么，按中文习惯组织语序、拆分长句，删掉只为套用英文句式而存在的连接词。

- 英文：The planner inspects the returned observation after each tool call and selects the next action.
- 翻译腔：规划器在每一次工具调用之后检查被返回的观测，并且选择下一个动作。
- 中文：每次工具调用结束后，规划器查看返回的观测，决定下一步动作。

## 排版

- 中文句子使用全角标点：，。、；：？！“”（）——……。整句为英文时保留半角标点。
- 引号用 “”，嵌套时用 ‘’，不用「」。
- 中文与英文、中文与数字之间加一个半角空格，例如：在 ``libero_spatial`` 上运行 10 个任务。数字与单位之间加空格（24 GB、10 cm），% 和 ° 前不加。
- 全角标点前后不加空格。
- 并列词用顿号分隔，英文词同样用顿号：LIBERO、RoboCasa365、RoboTwin。
- 英文专有名词保持原有大小写（GitHub、MuJoCo、RoboCasa365），英文词不加复数后缀（写“多个 worker”，不写“多个 workers”）。
- RST 源文件中的中文段落和列表项保持单行，或在汉字换行处加反斜杠 `\` 转义换行（例如 `评测模式读取已有记忆，\` 下一行紧接 `按环境规定判断任务结果。`，仅用于汉字之间，表格与代码块内除外）；不要裸换行，否则渲染出多余空格。
- 行内代码或加粗紧邻汉字或全角左括号等字符时，加转义空格 `\ `（反斜杠加空格），避免 Sphinx 构建报错或吞字，详见 [../reference.md](../reference.md#inline-markup-next-to-cjk-punctuation)。

## 术语

- 代码标识符一律保留原文，不翻译：CLI 参数、环境变量、配置项、工具名、文件名、模型名、机器人标识符（如 `robocasa`、`--planner`、`_recipe.jsonl`、`terminated`）。
- 遵循 [glossary.md](glossary.md) 中的固定译法；开发者日常通用的英文词（如 `endpoint`、`worker`、`checkpoint`、`Dashboard`、`Flash Mode`）按上下文保留英文。
- 同一概念全文只用一个词，不在“环境”“仿真环境”“模拟器”之间随意切换。

## 句子

- **说人话、重易读**：用同行一眼看懂的平实技术中文写清楚，不堆砌抽象名词或读两遍才懂的长句。
- 一句话说一件事，分句尽量不超过 40 字，一逗到底的长句拆成短句。
- 多用主动句，让执行动作的主体作主语（“规划器读取记忆”，不写“记忆被规划器读取”）。
- 删掉空动词：“进行评测”写成“评测”，“实现了对……的支持”写成“支持……”，“提供了……的能力”写成“可以……”。
- 不照搬英文从句结构：
  - `when`：“当……时”多数改成“……后”或“……时”。
  - `for` / `regarding`：“对于每个任务来说”写成“每个任务”；删去多余的“关于”“有关”。
  - `through` / `by`：“通过……的方式”改成直接说怎么做。
  - `allow` / `enable`：“允许你……”“使……能够……”写成“可以……”。
  - `based on`：只在确为依赖基础时用“基于”，其余用“用”“按”“根据”。
- 删去多余的“一个”“你的”“其”“该”；指代不清时直接重复名词。
- 少用连续的“的”；用具体数字代替模糊程度词。

## 语气

- 书面、直接、克制。不写聊天口语（“看看长什么样”“等需要时再看”“不用跟着改”），也不写公文腔（“本文旨在”“进行相关操作”“倘若”）。
- 称呼读者用“你”或省略主语，不用“您”。
- 不夸张，不用“强大”“无缝”“完美”“最先进”“一站式”。
- 不用“值得注意的是”“需要注意的是”开头；重要提示直接写事实，或放入 `.. note::` / `.. warning::`。
- 不用“首先……其次……最后……”串联步骤；改用有序列表。
- 不反复用“这不是 A，不是 B，而是 C”“并非……而是……”做正反面排除对比；直接说它是什么、做什么。
- 不写“本节将介绍”“接下来我们来看”等预告句。

## 标题和列表

- 标题简短明确，任务标题用“动词 + 对象”（如“运行一个任务”“查看结果”），末尾不加标点。
- 列表前用一句话引出；列表项格式一致，全为完整句子时句末加句号，全为短语时不加。
- 仅在步骤顺序重要时使用有序列表。

## 常见翻译腔，对照改写

| 翻译腔 | 中文 |
|---|---|
| 修正后的安装器不再覆盖旧资源。 | 内容不同的已有资源会保留；使用 ``--overwrite`` 可替换安装范围内的资源。 |
| 它允许你在独立环境中运行任务。 | 可以在独立环境中运行任务。 |
| 对于每一个环境来说，…… | 每个环境…… |
| 当下载完成后，运行以下命令。 | 下载完成后，运行以下命令。 |
| 对模型进行评测。 | 评测模型。 |
| 值得注意的是，规划器调用 ``finish`` 不代表任务成功。 | 规划器调用 ``finish`` 不代表任务成功，应以环境最终状态的 ``terminated`` 为准。 |
| 本节将介绍如何配置规划器。 | 删去，直接写配置步骤。 |

## 自查

- [ ] 遮住英文页，中文页读起来依然通顺自然，像中文工程师直接写的。
- [ ] 全文没有“您”“值得注意的是”“「」”，“进行”“被”“当……时”只留在必要处。
- [ ] 中英文、数字之间有空格，中文句中无半角标点，段落无裸换行，行内标记边界正确。
- [ ] 术语与 [glossary.md](glossary.md) 一致，同一概念用词统一。
